# 防御设施

> 实现：`src/galaxy/26_fortify.galaxy`，工人调度在 `30_workers.galaxy`。
> 规则来源：`usr/Defense.md`（策划侧），基线 6.2。

**位置（location）= 房间或走廊。**两者都是带工事点位的 region、都吃等级，所以代码里不区分。

## 钱和时间是两种代价

升级**立刻完成**，而且位置的等级**永不下降**，无论多少建筑被摧毁。

不立刻的是**建筑**：工人 SCV 得走过去把它盖起来，之后永远免费修复和重建。所以**付钱**是一个关于矿的决定，**拿到东西**是一个关于你十分钟前造了几个工人的决定。

两条规则咬在一起，产生了一个值得注意的后果：

- 上一等级全部建成前不能买下一级
- 持续挨打的建筑永远盖不完

**⇒ 一个正在被打穿的地方是加固不了的。**你得先赢下这场架，再买答案。这和临阵买防御正好相反，是故意的。

## 免费修复是因为建筑本身不要钱

SC2 的 Repair 按单位自身 `Cost` 的一部分收费。所以"SCV 免费重建"是一个**数据决定**而不是脚本：**工事建筑 `Cost` 置 0，矿在升级那一步收。**修复和重建于是自动免费，一行代码都不用写。

同一个选择让**建造**也免费，所以建筑是**在一丝血上凭空立起来，剩下的交给工人修**。这不是在模拟建造，它**就是**建造：

```
建造时间 = 修复时间 → 随工人数量下降 → "scv 越多修建越快" 自动成立
```

整套里没有任何地方存在"建造时长"这个常数。

## 占用是问句柄，不是问类型

槽位记着**站在它上面的那个单位的句柄**（`gvg_slotUnit`）。原来是空间地问"这个坐标上有没有一个 `gvg_slotType` 类型的单位"，那是错的，而且错了两次：

- **会钻地的炮塔会改类型。**stock `PerditionTurret` 空闲时 morph 成 `PerditionTurretUnderground`（`CAbilMorph id="PerditionTurretBurrow"`），搜索找不到它了，槽位读作空，工人在同一格上一座接一座地堆炮塔。
- **被唤起的守军会走开。**`Fort_Rouse` 找不到它给第二个命令，归位检查也送不了它回家，因为两边看的都是**那个格子**而不是**那个单位**。

这和这个模块别处避免的"记账"不是一回事。**一本"哪些建好了"的账可以和世界不一致；一个单位句柄就是世界**，`UnitIsAlive` 替它回答。被换掉的不是账本，是**一个被当成身份用的描述**——而那个描述最后既配上了不止一个东西，又配不上全部。

## 建筑是被"下令建造"的，不是被创建的

**守军**用 `UnitCreate` 凭空生成——它不是盖出来的，它是折跃进来的。

**建筑**是给工人下**地图自己的 build 命令**，引擎负责剩下全部：走过去时的建造虚影、放下几乎 0 血的工地、SCV 锁在上面、计时器、取消按钮。

前面两版都想从外面模仿这件事，都失败了，两次的失败方式都值得记住：

| 试过的 | 为什么不行 |
|---|---|
| 8% 血 + 让工人维修 | `Repair` 的 `TargetFilters` 排除 `UnderConstruction`，**SCV 根本不被允许修没盖完的建筑**，命令被直接拒。而且 Terran 建筑 1/3 血以下会自燃，8% 在线下，每座工事一立起来就在烧死自己 |
| `c_unitCreateConstruct` | 造出来的是**穿着工地外观的成品**——满血，而且会开火。没有任何建造在发生，只有一套戏服 |

**教训是同一条：建造不是一个能从外面刷到单位身上的状态，它是工人和工地之间的一种关系，而只有 build ability 能建立它。**所以代码不再试图当建造者，改成告诉建造者要造什么。

### 命令下标必须从数据里读

`(ability, index)` 这一对只存在于 catalog 的形状里：`CAbilBuild` 的 `InfoArray` 行就是它的命令，从 0 开始数。`gen_objects.py` 构建时从地图的 `AbilData.xml` 里读出来，emit 成 `ObjectsGen_BuildAbil` / `ObjectsGen_BuildIndex`。

不这么做的话脚本里就得硬写一个数字，而**任何人在它上面插一行，那个数字就错了**——而且是静默地错成盖出别的建筑。

（依据不是猜的：liberty 的 `thanson02` 用 `AbilityCommand("TerranBuild", 1)` 造出来的是 SupplyDepot，而 `Build2` 就是 SupplyDepot 那一行。）

**没有 build 命令的点位是惰性的**，不是坏的：`ObjectsGen_BuildIndex` 返回 -1，`Fort_JobFor` 跳过它，`-fort` 会打出 `(N have no build command)`。沉默的话它看起来就只是工人偷懒。

### 谁去建：问世界，不记账

`Fort_SlotClaimed` 遍历工人，看有没有谁**当前的命令**就是这个 build ability、且目标点就是这个位置（`UnitOrderHasAbil` + `OrderGetTargetPoint`）。

一份写下来的"认领"会比认领它的那个工人活得更久。

### 一座建筑多个 scv：那是安保部的升级

liberty 战役的 `AdvancedConstruction` 就是这件事，而且**纯 EffectArray，一行脚本都不用**：

```xml
<CUpgrade id="AdvancedConstruction">
    <EffectArray Operation="Set" Reference="Abil,BuildInProgress,MaxBuilders" Value="10"/>
    <EffectArray Operation="Set" Reference="Abil,BuildInProgress,PowerBuildBonusRate" Value="0.6"/>
    <EffectArray Operation="Set" Reference="Abil,BuildInProgress,PowerBuildCostFactor" Value="0.0"/>
</CUpgrade>
```

`MaxBuilders` 1→10、每个额外工人 +60% 速度、额外工人不额外收费。这正是 `12_departments.galaxy` 那套升级机制预设的形状。做成 `Netzach_UpgN_L` 抄这三行就行，代码侧零改动，而且升级逐玩家，天然不违反"不惩罚未犯错的玩家"。

**在这条升级之前，"更多 scv 更快"指的是同时开工的点位更多**——一个工人立起一座就走向下一座，整批更早完成。一座建筑一个计时器。

## 编辑器侧：摆真的单位，被读一次然后删掉

| | |
|---|---|
| region `room_*` / `corridor_*` | 一个位置 |
| group `fort1` / `fort2` / `fort3` | 一个点位，属于那个等级 |
| `CAbilBuild` 里的一行 | 这个建筑**能被造出来**，否则点位永远空着 |

**把真正的 `Lob_Turret_Basic` 或 `Lob_Guard_Marine` 摆在它该站的地方，加进对应等级的 group。**init 时读走它的类型、坐标、朝向、归属，然后把它删掉。以后盖起来的是同一个单位、同一个位置、同一个朝向。

这替换掉了原来的 marker 方案（`Lob_Fort_L2_Guard_Marine` 拆开解析成"2 级、变成 `Lob_Guard_Marine`"），而且在每一条上都更好：

- **没有平行的 marker 单位要建**，没有字符串解析，没有命名约定要记要拼对
- **所见即所得**。marker 告诉不了你炮塔**装不装得下**；摆在编辑器里的炮塔白送编辑器自己的摆放校验
- **朝向白来**，marker 方案还得再开一个通道装它

等级搬到了**编辑器 group** —— 这个通道项目本来就有，而且它**只覆盖预放对象**，正好就是"固定点位"的定义。

### 为什么是删掉而不是隐藏

隐藏是能做的：`c_unitStateHidden` 可写，`Selectable` / `Targetable` / `Paused` 也是。

但**隐藏的单位仍然占着它的 footprint** —— 一个 3 级炮塔位会从第 0 分钟起堵着自己那条走廊，而**没有任何 unit state 能关掉寻路阻挡**。

隐藏还意味着四个 flag 都得对，而漏掉任何一个都会变成一个看起来像别的问题的 bug：溅射打死一个看不见的炮塔、框选框住了空气。

读四个字段然后删掉，这些一个都没有，而且编辑器里仍然显示着将来会站在那里的东西。

> 所有字段必须在 `UnitRemove` **之前**读完。之后那个句柄是个死单位，每一个问题都会答错。

**变成 `Lob_Guard_*` 的是守军，会折跃进来；其余是建筑，要盖。**判定直接问 `ObjectsGen_IsGuard(unit)`，不查字符串前缀。

**点位有没有被占用是空间地问：**那个坐标上站没站着那个类型的单位。所以没有任何东西记账"哪个建筑属于哪个槽"，建筑死了槽自然就空了。

`Lob_Turret_*` / `Lob_Guard_*` / `Lob_Salvage_*` 三个前缀已经进 `EXPECTED_CATEGORIES`，单位建出来之前全表为空、功能惰性。

## 点位索引一次，敌人靠事件

点位**不可能改变** —— init 之后它们已经不在地图上了 —— 所以它属于哪个位置、是几级、变成什么，只在 init 定一次，之后再也不问。

（第一版每秒把全图 marker 扫一遍、对每个位置做一次 `RegionContainsPoint`，那是在反复重算一件不会变的事。）

敌人在不在则是相反性质的事实：它一直在变，而且几乎总是"不在"。所以它是**事件**不是轮询——`TriggerAddEventUnitRegion` 挂在每个位置上，有东西走进来才响，守军从那里被唤起。每秒问每个位置一遍"有事吗"然后得到"没有"，是同一种浪费换个方向。

留在定时器上的只剩"闲着的守军飘离了岗位"，那才是真正周期性的，而且它遍历的是索引好的槽而不是地图。

> **为什么位置的归属不用"单位进入区域"而用 `RegionGetCenter`：**那是一个关于**空房间**的静态几何问题。谁能升级它、建筑归谁，都是**在任何人走进去之前**就要回答的；没有单位可以进入的时候，进入事件答不了。

## 守军来一次，死了就是死了

**第一次**把某一等级的建筑全部立起来时，守军一次性折跃进入。买下一级时也会**补齐**更早等级的阵亡者。

**被打光之后重建，不触发增援。**

所以守军被清掉的位置会一直虚弱下去，直到有人再花钱，或者房间里的生产建筑补、或者中央本部的被动补——**后两者都还不存在**，代码里标了位置。

这让守军损失真的疼，免费复活不会。

## 资源回收装置（`Lob_Salvage_*`）

房间里的 0 级固定设施，慢速往**矿堆**里滴货。

它的职责很窄，写下来免得以后被误当成一套经济：**它是为了让"残骸全清完 + 异想体暂时做不了工"的空窗期不至于零收入且无事可做。**

**它进的是矿堆，不是玩家的矿。**这就是它不改变任何形状的原因——基线 4.4 那条"矿堆→物资全自动、靠矿工走"原封不动，这只是在**第一段**下面垫了个底，不是绕过第二段。玩家仍然需要矿工，矿工仍然要走，而一个矿堆里有货的玩家完全不受它影响。

速率故意很差。它是地板，不是策略。

## 位置名现在直接把 region id 给玩家看

`Fort_Upgrade` 的播报用的是 `gvg_locName[loc]`，而那是 region 的名字——玩家会看到 `corridor_b`。

其余玩家可见文本都进了 `src/strings/`（见 [`../../dev/pipeline.md`](../../dev/pipeline.md)），**只有这一条没有**，因为它的内容在编辑器里、还没有房间。等房间画好了，做法是给每个 `room_*` / `corridor_*` 配一个 `Lob/Place/<name>` 字符串——`gen_objects.py` 已经在解析 region 表，所以那道校验可以是构建期的。

## 待定

- **电力**。基线 4.3 说工事运行费电力，而 6.2 那条"电费由房主付还是出资者付"仍然待定。**当前实现完全不涉及电。**
- **跨部门升级权限**。规则在 `usr/department.md` 控制部协作命令里写好了（lv1 最高 1 级 / lv2 最高 3 级 / lv3、lv4 无限制），但地图里还没有升级树，所以 `Fort_UpgradeRefusal` 目前不拦——**不拦是因为没编，不是因为允许**。
- 生产建筑补充守军、中央本部跨房间补充守军。
- 守军 SCV（控制部技能召唤的）只修本区域建筑且无视 debris。

## 一条该改的旧文字

基线 6.1 写着"防守完全依赖玩家本人（**NPC 不参与战斗**）"。守军是会打仗的 NPC，控制部的巡逻队和培训部的自卫武器也早就越过这条线了。那句话过期了，不是和这份设计冲突。

## 调试

| | |
|---|---|
| `-fort` | 每个位置：等级、归属、立起来了几个 |
| `-fort N` | 在那里买下一级（顶替还不存在的房间 UI） |

`-fort` 会打出拒绝理由而不是静默失败——"上一级还没盖完"是玩家会不断撞到的规则，而一个没反应的按钮什么都教不会。
