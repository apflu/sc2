# 存档

> 实现：`src/galaxy/16_bank.galaxy`，压缩工具 `src/galaxy/02_codec.galaxy`。
> 设计来源：`design/agents-and-abnormalities.md` §8。这里写的是**实现层的决定和它们的理由**，不重复 §8 的论证。

## 存什么

只存**解锁，不存数值**。模型是 Risk of Rain 2 而不是 Deep Rock：跨局带走的是**能出现什么**的多样性，不是**谁更强**。

现在实际存的只有图鉴，因为它是 §8.1 那张清单上唯一已经存在的东西：

| | |
|---|---|
| 观察等级 | 每玩家 × 每异想体，0-4 |
| PE-Box | 每玩家 × 每异想体，用来买下一节 |

**还没存的**（各自出现时加一节，bank 的形状不用改）：异想体解锁池、任务进度、核心抑制进度、部门解锁、称号、纪录。

**永远不存**：员工属性、升级等级、资源、能源。§8.2 给了三条理由，第一条最强——**一个被持久化的数值会让角色强度变成在线时长的函数而不是水平的函数**，那就是最高设计原则反着写一遍。

PE-Box **是存的**，这是明确要求过的（"工作获得的 E-Box 会计入存档"）。它不属于 §8.1 禁止的那类数字：它买的是知识，永远不进战斗计算，而且**存储里根本没有能让它挪到另一个异想体上的索引**——`player × abnormality` 的二维格里不存在"总数"这个量。

## 多人同步是唯一难的部分

bank 是**本地文件**，而 Galaxy 在所有机器上锁步执行。读一个各机器不一致的文件并据此分支，那不是以后会发现的 bug，是**当场 desync**。

引擎的答案是：**已加载的 bank 是被同步的，`BankWait` 就是那道屏障。**这不是推出来的——暴雪自己的战役代码就是这么写的，而且把那个触发器直接命名成了 `ArchivesBankLoadSyncComplete`：

```
BankLoad(name, player)      然后在触发器里：  BankWait(bank)
```

`BankWait` 会阻塞，所以它跑在自己的触发器里，用 `TriggerExecute(t, true, false)` 启动（第三个参数是"等它跑完"，关掉）。init 不会卡在几个文件加载后面。

> **`BankPreload` 看着像是这里要用的东西，但它不是。**它在 `NativeLib.TriggerLib` 里没有 `<FlagNative/>`，两个参数都带 `<ParamFlagPreload/>`——那是编辑器在编译期收集的声明，不是手写 Galaxy 能调的函数。

## 两条防止它吃掉别人存档的规则

**读完之前一个字都不写。**在加载窗口里触发的自动保存会把一张空表盖到真存档上，而丢了四十局图鉴的玩家**没有任何办法知道发生了什么**。`gv_bankLoaded` 门住每一次写。

**保存由比较驱动，不由调用驱动。**改动观察等级的两个模块（13 买章节、14 加箱子）都排在 bank **之前**，调不进来；而为了修这个把 dirty 标志反向穿过模块顺序，比它要修的问题更糟。所以 bank 自己留一份"上次写下去的快照"，live 表和它对不上就存——行为一样，但没有任何人需要记得去通知谁。

## 签名开着，但不当门禁

§8.2.3：密钥在地图脚本里、扒得出来，而这正是"只存解锁不存数值"最强的论据，不是一个要去打的仗。

**改一个 flag，你解锁了本来也会解锁的内容；改一个数值会毁掉另外四个人的这局游戏——而这里没有数值可改。**

`-bank` 会把校验失败标出来，然后照常接受。

## 以后要压缩：能做，已经验过了

`02_codec.galaxy` 是这件事的**证据**，不是保证：base64 变长整数（每字符 5 位负载 + 1 位续位），加上把多个小字段叠进一个 int 的 `Codec_Put/Get/Drop`。`-codec` 跑边界值往返自检。8 个整数（含 30 位最大值）编码成 20 个字符。

语言侧的结论在 [`dev/galaxy-pitfalls.md`](../../dev/galaxy-pitfalls.md)：`<<` 和 `|` 确认可用，`>>` `&` `^` `~` 没有证据，所以 codec 用 `/` 和 `%` 代替，一个没见过的运算符都不押。

**现在没有任何东西用它，这是故意的。**bank 能跑，世界上还不存在任何一个存档文件，而把没测过的代码放进唯一一条能毁掉玩家进度的路径上，换的是没人缺的那点字节。

### 真正挡着"全部塞进一个 key"的不是编码，是排序

现在每个异想体一个 key、key 就是它的类型 id，所以**新加一个异想体不会移动任何已有数据**。

压成单串需要一个**稳定的逐异想体序号**。而这个序号一旦来自"文档排序后的下标"，加一份文档就会把所有人的存档错位。

这是个文档侧的决定，和残余管理难度、"危险" tag 是同一类问题。**不要随手挑一个**——上一次凭空推导出 `User2` attribute 就是这么来的。

## 调试

| | |
|---|---|
| `-bank` | 内存里的和磁盘上的并排对比（唯一有意思的 bank 问题就是它们一不一致） |
| `-bank save` | 立刻写 |
| `-bank wipe` | 扔掉。存在的理由是"新账号能不能正常开局"否则只能问一次 |
| `-codec` | 压缩器的往返自检 |

完整验证要跑两局：第一局 `-bank wipe` → 工作攒箱子 → 买观察等级 → 退出；第二局开局 `-bank` 应该看到等级还在。
