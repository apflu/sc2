# 考验（Ordeal）

> 代码在 `27_ordeals.galaxy`。难度上限的理由在 [`difficulty.md`](difficulty.md)，四个 Dawn 的原作资料在 `docs/usr/ordeals/`。

## 考验没有自己的时钟

它**不是被安排的，它是熔毁等级的后果**。

```
熔毁 2        → Dawn
熔毁 3 / 4 / 5 → Noon
熔毁 6 / 7     → Dusk
熔毁 8 及以上   → Midnight
```

`13_meltdown` 把一个等级变成"需要被处理的收容单元"，这个模块把**同一个等级**变成"走进来需要被杀掉的东西"。两者是同一股压力从两扇门进来。

给考验一个独立计时器会让它和融毁**偶然地撞在一起**，而那是一个没人设计过的难度尖峰。

## 难度是天花板，不是日程表

`Diff_OrdealCap()` 返回全桌难度，考验等级取 `min(等级要求, 上限)`。

**是钳制，不是跳过。**Casual 上 Dawn 会一直来、永远不变强——节奏和能源奖励都完整保留。跳过的话 Casual 全局只会出现一次考验，那是**另一个游戏**，不是一个更简单的游戏。

## 抽哪一个，由存在的单位决定

`Lob_Ordeal_Dawn_Amber` 会落进生成的 `Ordeal_Dawn` 表，所以**某一档的候选池就是为它建过的单位**。

> **加一个考验 = 建一个单位。这个文件一个字都不用改。**

某一档没有单位就抽不出东西，`-ordeal` 会直说 `NOTHING -- no units authored for that tier`。惰性，不是坏了。

命名按约定：`Lob_Ordeal_<档次>_<名字>`。

| | |
|---|---|
| `Lob_Ordeal_Dawn_Amber` | 琥珀之黎明 |
| `Lob_Ordeal_Dawn_Crimson` | 绯红之黎明 |
| `Lob_Ordeal_Dawn_Green` | 翠绿之黎明 |
| `Lob_Ordeal_Dawn_Violet` | 紫罗兰之黎明 |

**名字不另写字符串。**`Ordeal_NameOf` 直接读单位自己的 `Unit/Name/<type>`——编辑器已经写过一次，面板已经在显示它，再写一份 `Lob/` key 就是一份会漂移的副本。

## 提前知道是设计的一部分

下一次考验在**上一次被派发的那一刻**就抽好并公布：类型 + 会在哪个熔毁等级降临。

这不是贴心，这是考验在降临前那十分钟里**全部的战术内容**。惊喜是没法准备的，而准备就是这个游戏本身。所以：

- 每次抽定都发一条字幕
- 目标面板常驻一条**状态行**（`Lob/Objective/Ordeal/*`）：闲时写"下一次：X，熔毁 N 级"，打起来写"镇压 X (2/5)"

这条是 **bonus objective**——考验付的是能源，而能源在船离开时就花掉了。和能源指标本身是同一条理由。

## 奖励是能源指标的百分比

| 档次 | 奖励 |
|---|---|
| Dawn | 10% |
| Noon | 15% |
| Dusk | 20% |
| Midnight | 25% |

**是指标的百分比，不是当前池子的。**一次考验的价值不该取决于你此刻宽裕还是紧巴——档次已经是难度轴了，池子不是。

## 一个部门一只，而"一只"是个占位

每个在座玩家的一条走廊/房间里生成一只，位置从 `26_fortify` 的地点表里随机取（没画区域就退到核心）。

**数量没有做。**原作里琥珀之黎明的虫子五只一群、小丑单独行动——**"来几只"是一个逐类型的数值**，而这个项目**还没有逐类型数值的通道**。那个决定同时挡着残余管理难度、存档要的逐异想体序号、和工具异想体标志（见 [`../build-order.md`](../build-order.md)）。

**不要为了让数量能动就在这里新开第四条通道。**现在一个部门一只。

## 每种考验自己的行为也没有做

四份原作资料里的机制——虫子钻地换走廊、小丑偷 PE 箱并把 Qliphoth 减 1、机器人处决时溅白伤、紫罗兰自爆把整个部门的 Qliphoth 清零——**一条都没实现**。

已经做的是**框架**：排期、预告、随机抽取、生成、追踪、判定全灭、发奖、播报、计数。血量/伤害/移速/四抗是单位数据，归编辑器侧。

单独行为等单位建出来再逐个做，那时候它们才有东西可以附着。

## 任务

控制部 4「熬过一次黄昏考验」和惩戒部 4「熬过一次午夜考验」已经接上 `Ordeal_BeatenAtLeast`。

**按"至少这一档"算**——一次午夜也满足黄昏那条。要求"恰好黄昏"会让任务在夜色变深时反而更难达成，那是反的。

计数是**全桌**的：考验在每个部门同时降临，最后一只倒下时结束，没有一个可以分给某个玩家的半边。和培训部 3 同一个道理。
