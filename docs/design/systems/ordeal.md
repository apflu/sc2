# 考验（Ordeal）

> 代码在 `27_ordeals.galaxy`。难度上限的理由在 [`difficulty.md`](difficulty.md)，四个 Dawn 的原作资料在 `docs/usr/ordeals/`。

## 考验没有自己的时钟

它**不是被安排的，它是熔毁等级的后果**。`13_meltdown` 把一个等级变成"需要被处理的收容单元"，这个模块把**同一个等级**变成"走进来需要被杀掉的东西"。两者是同一股压力从两扇门进来。

给考验一个独立计时器会让它和融毁**偶然地撞在一起**，而那是一个没人设计过的难度尖峰。

## 一晚四场，每档一场

| 档次 | 熔毁等级 |
|---|---|
| Dawn | 2 |
| Noon | 3 / 4 / 5 之一 |
| Dusk | 6 / 7 之一 |
| Midnight | 8 |

**那几个数字是范围，不是几次机会。**具体落在哪一级**在开局时就抽好**——所以整晚的日程在第一分钟之前就已经存在，`-ordeal` 能一次全部打出来。

> 第一版把范围读成了"里面每一级都来一次"，结果是三场 Noon，然后从 8 级起每一级一场 Midnight。**一个反复回来的考验不是升级压力，是一个披着考验名字的刷怪计时器。**

## 难度是跳过，不是削弱

`Diff_OrdealCap()` 之上的档次**根本不出现**。

Casual 的一晚就是**一场 Dawn，然后没有了**。钳制成"永远只来 Dawn"不是更温和的一晚，只是更长的一晚——而且那意味着 Casual 反而是考验场次最多的难度。

## 抽哪一个，由存在的单位决定

`Lob_Ordeal_Dawn_Amber` 会落进生成的 `Ordeal_Dawn` 表，所以**某一档的候选池就是为它建过的单位**。

> **加一个考验 = 建一个单位。这个文件一个字都不用改。**

某一档没有单位就抽不出东西，`-ordeal` 会直说 `NOTHING -- no units authored for that tier`。惰性，不是坏了。

命名按约定：`Lob_Ordeal_<档次>_<名字>`。

| | |
|---|---|
| `Lob_Ordeal_Dawn_Amber` | 琥珀之黎明 |
| `Lob_Ordeal_Dawn_Crimson` | 绯红之黎明 |
| `Lob_Ordeal_Dawn_Green` | 翠绿之黎明 |
| `Lob_Ordeal_Dawn_Violet` | 紫罗兰之黎明 |

**名字不另写字符串。**`Ordeal_NameOf` 直接读单位自己的 `Unit/Name/<type>`——编辑器已经写过一次，面板已经在显示它，再写一份 `Lob/` key 就是一份会漂移的副本。

## 提前知道是设计的一部分

下一次考验在**上一次被派发的那一刻**就抽好并公布：类型 + 会在哪个熔毁等级降临。

这不是贴心，这是考验在降临前那十分钟里**全部的战术内容**。惊喜是没法准备的，而准备就是这个游戏本身。所以：

- 每次抽定都发一条字幕
- 目标面板常驻一条**状态行**（`Lob/Objective/Ordeal/*`）：闲时写"下一次：X，熔毁 N 级"，打起来写"镇压 X (2/5)"

这条是 **bonus objective**——考验付的是能源，而能源在船离开时就花掉了。和能源指标本身是同一条理由。

## 奖励是能源指标的百分比

| 档次 | 奖励 |
|---|---|
| Dawn | 10% |
| Noon | 15% |
| Dusk | 20% |
| Midnight | 25% |

**是指标的百分比，不是当前池子的。**一次考验的价值不该取决于你此刻宽裕还是紧巴——档次已经是难度轴了，池子不是。

## 一个部门一只，而"一只"是个占位

每个在座玩家的一条走廊/房间里生成一只，位置从 `26_fortify` 的地点表里随机取（没画区域就退到核心）。

**数量没有做。**原作里琥珀之黎明的虫子五只一群、小丑单独行动——**"来几只"是一个逐类型的数值**，而这个项目**还没有逐类型数值的通道**。那个决定同时挡着残余管理难度、存档要的逐异想体序号、和工具异想体标志（见 [`../build-order.md`](../build-order.md)）。

**不要为了让数量能动就在这里新开第四条通道。**现在一个部门一只。

## 每种考验自己的行为

绝大部分考验**不需要脚本**：血量、伤害、移速、四抗全是单位数据。需要脚本的是那些**没法用属性表达**的，目前两条：

### 绯红：抢完就走

不主动攻击（它连 `attack` 技能都没有）。它挑一个**自己部门的、门还立着的、处于收容状态的**收容单元，然后**对那扇门施放 `Lob_Ordeal_Rob`**——一个和 `Interact` 同形状的技能：同样的 `Range 4`、同样的 `TargetFilters`、`PrepTime` 就是那 20 秒、`ShowProgressArray` 让引擎画进度条。

**它不是用脚本计时器模仿读条，它就是在读条。**所以读到一半被打死＝什么都没拿走，而这正是它值得被打的原因。脚本这边只负责下命令和听 `c_unitAbilStageComplete`，一秒都不数。

> **第一版站着不动，是因为命令瞄的是异想体而不是门。**异想体在墙后面，寻路到不了，所以那条移动命令永远走不完——静默地。门才是能被瞄准的那个东西，而 `Range 4` 和 `Interact` 用同一个数字也是同一个理由：**门是一个墙体 footprint，射程是从一个谁也站不上去的中心量的。**

读条走完之后：

- 拿走那个单元 **30% 的 PE 箱**（从**单元主人**的那一份里扣——那是谁的研究就扣谁的）
- **Qliphoth 计数器减 1**

然后原地消失、在本部门另一条走廊出现、重挑一个，直到被打死。

自己部门没有可抢的单元时会去抢别人的。**没有单元可抢就站着不动**——那是一个空手而归的小丑，不是一个卡住的状态机。

被抢的人会收到一条播报。**一次没人被告知的失窃和计数器的 bug 无法区分。**

### 紫罗兰：一个必须被处理的计时器

引信 **60-70 秒，逐个抽**，所以各部门不会同一秒一起炸。烧完：

- 那个部门**所有异想体的 Qliphoth 归零**
- 那个部门**所有员工吃 10-14 白伤**
- **整场考验提前结束，而且不发奖**

最后一条是关键：`Ordeal_End(false)` 走的是失败分支。**如果自爆也能拿到能源，那么无视紫罗兰就成了最省事的刷能源方式**，而它存在的全部意义正好是不能被无视。

> **`BanelingExplode` 已经从紫罗兰身上摘掉了，连同 `VolatileBurstDummy` 装备和那个指向不存在技能的 `Explode` 按钮。**它是一个 `DeathResponse`，死亡时放 `VolatileBurst`——**20 点真实溅射伤害，对轻甲还 +15**，打在附近的员工身上。那不是"炸得好看"，那是一发绕过了整个伤害系统的实弹。复制单位时跟进来的东西会安静地生效，这是第二次。

### 绯红的死亡爆炸

被打死时，**半径 2.0 内所有员工和玩家吃 10-15 红伤**（一次掷点，所有人同一个数——同一声爆炸给两个并排站着的人 10 和 15 会像 bug）。这是绯红**唯一**一次造成伤害：活着的时候它从员工身边走过去，看都不看。

### 为什么爆炸不是技能

两场爆炸都拆成了**画面**和**数字**两半：画面是 `Ordeal_Boom` 在一个点上丢一个模型，数字是 `Emp_CombatDamage`，在脚本里。

复制一个 Baneling 的 `VolatileBurst` 看上去正好能干这活，但它三处都不行：

- **`CEffectDamage` 说不出白伤。**引擎只有 `Amount` 和 `Kind`（Melee / Ranged / Splash / Ability），没有任何一个字段的意思是"扣理智"——理智是我们的，目录里没听说过它。紫罗兰的自爆是白伤，所以目录连一半都交不出来。
- **`CEffectDamage` 说不出"这个部门"。**`AreaArray` 是个半径，而紫罗兰的范围是**分配到该部门的员工**，他们可能站在地图上任何地方，包括别人的收容单元旁边。大到能罩住他们的半径也会罩住不该碰的人。
- **绯红的红伤引擎明明算得了，也仍然不能交给它。**引擎打出的伤害不经过 `Emp_CombatDamage`，于是会绕过 `Emp_DamageScale`（E.G.O 抗性要落的那个接缝）、绕过"生命归零即死"（员工没有倒地状态）、也绕过 `Emp_DamageShown`。

最后一条是最贵的：**`Emp_DamageShown(who, type, amount, source)` 是情报部伤害显示要挂的钩子**，现在是空的，但每一条伤到人的路径都已经在调它了。红伤会自己喊出来——血条会动，玩家从新手教程起就在读那根条；**白伤不会**，SP 是我们的东西，引擎不画它的条，一个在门口吃了 14 白伤的员工看起来和什么都没吃的员工完全一样，直到他定住的那一秒。**一份玩家观察不到的代价，是一份他学不到东西的代价**，而学会哪个异想体收哪种账就是这个游戏本身。

所以：没有 `CAbilEffectInstant`，没有 `CEffectDamage`，没有自杀效果。一个模型和一次函数调用。

> 类型 → 是否死亡爆炸另起了一张表（`Ordeal_BlastsOnDeath`），没有并进 `Ordeal_ActOf` 的枚举。**"抢东西"和"炸"是关于绯红的两件事，不是一件**，而且马上就要分家：翠绿的处决溅射要的正是这个死亡钩子，且和收容单元大门毫无关系。并成一个枚举会逼翠绿假装自己是小偷才能拿到死亡事件。

### 类型 → 行为的映射是一张硬编码的表

`Ordeal_ActOf` 里按单位 id 逐条判断。**这是唯一一处考验的单位 id 出现在脚本里的地方**，值得别扭一下。

它没有做成通道，是因为**还没有逐类型数值的通道**，而在这里新开一条正是 `build-order.md` 那条注记禁止的事。不在表里的类型就只是"会打架"。

### 翠绿：处决时溅白伤

普通攻击是红伤，近战，一次挥击两下（Zealot 的双刃）。真正的机制在它**已经赢了之后**：

**补刀五次，每次对房间里其他所有人 3 点白伤。**死掉的那个人什么都不付——他已经死了。

**这个反转就是全部内容。**资料里那句"机器人快要杀死某人时不要派人去压制"，理由正是：**赶到就等于进了那个房间。**十五点白伤在工作伤害的尺度上是天文数字，而且必须是——**看着同事被拆开是丢掉一个房间最快的方式。**

> 它挂在**一次命中**上，不是挂在死亡事件上，所以代码在 `28_damage.galaxy` 而不是这里。致命一击走的是 `Emp_CombatDamage`，那里面自己调 `UnitKill`，所以等到任何东西听见死亡事件时，**攻击者已经不在记录里了**。在命中落下的地方问一句"这一下是不是打死了"，不需要任何账本。

「房间」优先用画好的区域（`Fort_LocOfPoint`），没画区域的走廊退回半径 8。**退路是必要的**：地图上大部分地方还没有区域，而一次谁也没打到的处决看起来是机制坏了，不是地图没画完。

### 还没做的

虫子钻地换走廊。

还有一件更大的：**考验的普通攻击也走不了引擎。**紫罗兰的资料是黑伤 1-3，而黑伤和白伤一样在目录里不存在；绯红没有攻击所以暂时不痛不痒。`CWeapon` 没有 `ValidatorArray`，也没有任何一个字段能说"这一下扣理智"。等到某个考验真的要在活着的时候伤人，它得和爆炸走同一条路——武器只负责节奏和动作，数字仍然从 `Emp_CombatDamage` 出去。**这和 E.G.O 武器是同一个问题的两面**，值得一起解决而不是各修一次。

## 任务

控制部 4「熬过一次黄昏考验」和惩戒部 4「熬过一次午夜考验」已经接上 `Ordeal_BeatenAtLeast`。

**按"至少这一档"算**——一次午夜也满足黄昏那条。要求"恰好黄昏"会让任务在夜色变深时反而更难达成，那是反的。

计数是**全桌**的：考验在每个部门同时降临，最后一只倒下时结束，没有一个可以分给某个玩家的半边。和培训部 3 同一个道理。

## 测试

```
-ordeal                 候选池、整晚日程、上限、下一场
-ordeal now             把排期中的那一场提前打掉（会消耗掉它）
-ordeal dawn|noon|dusk|midnight
                        额外开一场，不动日程
```

打起来之后 `-ordeal` 会逐个打印实体在干什么：

```
ordeal RUNNING Lob_Ordeal_Dawn_Crimson (Dawn)  standing 1/1  pays 30
  ent 0 p1 on O_03_03
```

`idle -- no cell to rob` 表示它找不到可抢的单元；`marked X but not ordered` 表示命令没下出去，那是真的坏了。

两条不一样，而且都需要：`now` 走的是**系统里真实的那条路**（消耗排期、重新排下一场）；点名档次是**旁路**，用来在没走到熔毁 8 级的时候看一眼午夜，或者在 Casual 上测一个本该被跳过的档次。

等到熔毁 8 级才知道午夜会不会生成，那不叫测试。
