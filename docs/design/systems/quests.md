# 任务

> 实现：`src/galaxy/60_quests.galaxy`。计数器散落在事件发生的模块里，见下。
> 规则来源：`usr/quests_unlocks.md`（策划侧）。

每个部门四条任务，九个部门，共 36 条。**其中 11 条现在能数。**

## 一条规则决定了它长什么样

**能算出来的就算，只有会抹掉自己证据的才计数。**

绝大多数任务问的是**现在的状态**，而状态已经存在别处了：几个员工到了 II 级、某个位置几级、百科读到第几段。这些每 tick 现问，模块里一个字节都不存——**没有计数器，就没有和被计数物脱节的计数器**。

只有四件事不行，因为它们问的是**事件**，而等你回头看的时候证据已经没了：

| 事实 | 存在哪 | 为什么不能算 |
|---|---|---|
| 完成了几次工作 | `14_work` `gvg_workFinished` | 工作行被 `Work_Drop` 抹掉 |
| 其中几次结果为优 | `14_work` `gvg_workGood` | 同上 |
| 干净处理了几轮融毁 | `13_meltdown` `gvg_meltClean` | 轮次边界不留痕 |
| 镇压过哪些异想体 | `13_containment` `gvg_contSuppressed` | 异想体会复活，回到原样 |

**这四个计数器都放在事件发生的那个模块里，不放在这里。**因为那个模块是唯一看得见事件的地方。放在别处就要把事件转发过来，而转发出来的事件，等哪天有人给这件事加了第二条发生路径，就会被漏掉。

## 模块号 60 是被推上去的

它要读员工、收容、融毁、工作、部门、工事——Galaxy 要求全部先声明。能排到最后是因为**没有任何东西调用它**：任务只观察，不参与。

## 界面是原生任务面板

引擎已经在画它、排序、完成时打勾、分两栏、整局保留——这些自己写一遍只会更差。

两个 native 撑起全部：

| | |
|---|---|
| `ObjectiveCreateForPlayers` | **逐玩家**，所以六个人六个部门各看各的 |
| `ObjectiveSetName` | 进度写在**名字**里，`(2/4)`——这是 Blizzard 战役自己的写法 |

索引是 `player * 4 * 2 + n * 2 + step` 而不是按任务 id，因为**一个玩家永远只有自己部门的四条**（每条最多两行，见下）。所以是 128 项不是 576 项，换部门就是拆掉重建，不用搜。

**只在数字真的动了才重写名字。**否则每 2 秒对每个人的每一行都重建一次字符串，而绝大多数时候结果和面板上已有的一模一样。

### main / bonus 的分界是"记录 / 今晚"

引擎那两栏在字符串表里就叫 `Main Objectives` 和 `Bonus Objectives`。分在这条线上的**不是挑战与普通，是这一条做完之后还在不在**：

| | |
|---|---|
| **Main** | 已经在你记录里的那几条，**加上这局唯一能记进去的那一条** |
| **Bonus** | 你这局往后开出来的每一条（做完只算今晚），以及今晚的能源指标 |

所以玩家在花一整晚去做某件事之前，看得见**这一晚本身是目的，还是它之后的东西才是**。这个问题"挑战 / 普通"那种分法答不了。

## 一局只能存一格

部门的四条是**递进的**：第二条要等第一条做完才能着手。加上一条规则，整个进度模型就出来了：

> **你还没记录下来的第一条，就是这局能记录的那一条。**再往后的都还能做完，但只算今晚。

拿控制部、记录为 0 的玩家举例：

1. 能进记录的只有**控制 1**，它挂在 Main
2. 做完之后它留在 Main、保持完成状态
3. **控制 2 这时出现在 Bonus 里**——因为控制 1 做完了才轮得到它
4. 控制 2 就算做完也进不了记录，只给这局的奖励。**下一局它又是锁着的**

四局四条，而且每一局都值得在"不再计数之后"继续打下去。

### 记录是一个数，不是一个集合

因为四条是递进的，"哪几条做完了"永远是个**前缀**，而前缀是一个数。`gvg_questSaved` 就是这个数，逐玩家逐部门——**九个小整数一个玩家，这就是整个任务系统的持久化开销**。

它**只在局与局之间变**。局内记录数是固定的，所以"这局唯一可存的那一条"是个常量下标，而不是随着你打会往前爬的东西——否则做完主任务会顺手把下一条也变成可存的。

### 未开启的任务是 hidden，主任务例外

没轮到的任务建成 hidden，由 `Quest_Complete` 在前一条打勾的那一刻放出来——**这条链自己演给玩家看，不用讲**。

不可数的 **bonus** 任务保持隐藏：面板是给玩家看的，看不见的任务在那里只是噪音。但不可数的 **main** 任务照样显示，因为藏起来会让一个卡住的部门看起来像做完了的部门——那是两个谎里更糟的那个。tooltip 会说它为什么动不了。

`-quest` 无论如何都列全 36 条。

### 一条任务可以是两行

控制部 1 是「建立一个正常运转的收容单元 **并** 升级任意房间或走廊的防御设施」——两件不相干的事被一个"并"字拴在一起。当成一个计数器它显示 `(1/2)`，**只说了你走了多远，一个字都没说缺的是哪一半**。

拆成两条面板行，不用一个字就说清楚了：

```
Main Objectives
  ✓ Keep one containment cell running
  ☐ Fortify a room or corridor
```

**两条必须同时成立**，任务才算完成。这不用额外写规则——步骤是**推导的**不是闩住的，每 tick 重读一次，所以先买了工事、后来单元坏了，第一行会自己**取消打勾**，任务退回未完成。**只有任务本身闩住。**

一个能取消的勾看着不寻常，但那正是"同时成立"这条规则在自己现形。要画一个会不再成立的条件，这是唯一诚实的画法。

惩戒部 2（"3个HE级以上 **以及** 2个WAW级以上"）也是同一个形状，一并拆了。上限就是 2——文档里没有三段的任务，真出现了就是改一个常量加四个数组字面量。

拆开的任务两行都在同一栏，因为它们**是一条任务**。tooltip 上标着 `(1/2)`、`(2/2)`，以及一句"两半必须同时成立"。

### 只有两块文本，不是三块

`UI/Layout/UI/ObjectivePanel.SC2Layout` 里，**name 是列表行，description 就是 `ObjectiveTooltip` 的 `TipLabel`**——描述即悬停提示，不是两个槽。

所以那一个 tooltip 装：部门与序号、note（如果有）、**这一条算不算数**、以及"这个系统还不存在"（如果是那种）。

奖励按**完成数**写不按具体任务写，因为 `usr/department.md` 就是这么定的（"与其已完成的任务数有关"，四档对四条）。真正随任务变的是**它算不算进记录**，而那取决于它相对记录的位置，不取决于它是哪一条。

## 文本全在 `src/strings/enUS.txt`

代码里一个玩家能看见的英文都没有，只有 key：

```galaxy
Quest_Declare(c_qMalkuth3, 3, true, "Lob/Quest/Title/Malkuth3");
```

行内英文是一份已经丢掉的翻译。构建会检查引用了却没定义的 key 并**直接报错**——缺字符串在游戏里渲染成**空**，看起来像布局 bug 而不像缺文本。细节见 [`../../dev/pipeline.md`](../../dev/pipeline.md)。

> `-quest` 的输出**不**走这条路，它是开发者文本。但它要打印任务标题，而 Galaxy 有 `StringToText` 没有 `TextToString`，所以那几行是全程按 `text` 拼的（`Debug_SayText`）。

## 只数自己部门的任务

有两条任务写着"本部门"，其余也都是从某个部门的职责内部写的。`Quest_StepProgress` 对部门外的任务直接返回 0，而不是去算一个必然错的数。

## 完成是单向闩

进度会掉——员工会死、建筑会被夷平、培训部核心抑制会把属性压下去。**做过就是做过。**所以完成是个只能置位的 flag，进度只用来决定要不要置位。

## 轮次不是格子

控制部 3 数的是**轮**，而 `Melt_AnsweredBy` 数的是**格**。一轮里答四个和四轮里各答一个不是一回事，而且被 HELD 的格子能跨好几轮，所以两者推不出彼此。

判定：**这一轮里被点名过至少一个，且一个都没漏。**没被点名不算成就，三个答好第四个归零也不算。

实现是在 `Melt_Advance` 顶端拿上一轮的快照做差——这样一个跨越轮次边界的格子会落在**它真正被回答的那一轮**，而不是被点名的那一轮。

## 数不了的 25 条

它们照样声明，带着文档里的目标数，标成 `countable = false`。这样每个部门仍然是四条，解锁链可以对着一个不会再变的形状写。

`-quest` 会打印**"no channel yet"而不是 0/1**。一条没人开始的任务和一条地图根本观察不到的任务，写成数字长得一模一样，而只有一条值得去做。

缺口分四类：

| | 数量 | 缺什么 |
|---|---|---|
| 考验类 | 4 | Ordeal 系统 |
| 完赛评定类 | 4 | 局终钩子 |
| 击杀虫后 | 1 | 那个单位类型 |
| 文档空白 | 2 | 安保部 2/3 |
| 未列出的部门 | 14 | 中央本部、福利部、记录部、提取部 |

## 还没做

- **持久化。**`gvg_questSaved` 全是 0，`Quest_SetSaved` 是 `16_bank` 将来写进去的钩子。**现在没有任何记录能跨局活下来**，所以每一局你都只能存控制部 1。用 `-quest saved N` 假装你带着 N 条记录进场，这是现在唯一能看到第二、三、四局的办法。
- **奖励。**完成时什么都不发。部门被动和解锁链（"解锁：完成4个任务"）将来读 `Quest_DoneCount`。
- **惩戒部 2** 要按部门归属统计压制，而镇压账本是**全桌**的（培训部 3 明写"队友的进度也计算在内"）。两条任务问的是不同的问题，需要第二个账本，不是改第一个。

## 调试

| | |
|---|---|
| `-quest` | 你所在部门的四条，各自标着 `[record]` / `[MAIN]` / `[bonus]`，以及进度、DONE、`(locked)` 或 "no channel yet"。拆开的任务在这里也是两行 |
| `-quest 0-8` | 先把你换到那个部门（面板会跟着重建） |
| `-quest saved N` | 假装你带着 N 条记录进场——唯一能看到后面几局的办法 |

没有选择界面，部门是轮流发的，所以一个人测不到另外三套——`-quest N` 就是为此存在的。
