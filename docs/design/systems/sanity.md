# 理智（SP）

> 代码在 `11_employee.galaxy`（值与状态）、`14_work.galaxy`（拒绝派工）、`09_sector.galaxy`（休息室回复）。
> 行为在 `BehaviorData.xml` 的 `Lob_Panicked` 与 `Lob_Panicked_Hero`。
> 这一页**覆盖**基线 §8 里关于崩溃与恢复的写法。

## SP 就是 Energy vital

不是一个脚本数字外面画条 bar。引擎本来就有第二条 vital：单位面板会画它，behavior 能改它，它有上限、当前值和回复率。员工不施法，所以这一条是白捡的。

**谨慎（Prudence）一点换一点上限**，一条 per-point Modification，零脚本。

## 崩溃是**闩住**的

```
SP 归零   → 闩上
SP 回满   → 才松开
```

不是对称的，而这个不对称就是设计本身：

- **回来的路是别人拿白伤 E.G.O 打你**。阈值只要低于满值，任何一点零散回复都能把一个崩溃的人直接塞回工位。
- **"打到满"是一个人一段注意力的量**，"打一下"不是。恢复因此是一个决定，不是一次触发。

`SP_Add` 是唯一的闸口，所以钳位和闩锁都只有一处。

## 恢复：只有纯白伤

**同一发子弹，拆掉异想体的精神，装回员工的精神。**

**只有纯白伤。**黑伤同时打 HP 和 SP，但它**不回复任何东西**——它是一个混合伤害类型，不是"白伤加送"。红伤和苍伤更不用说。

这不是一个特例分支，它是白伤这个类型的定义在两种受体上的两种读法——所以它落在**武器数据里**，不在脚本里：

```xml
<CEffectSet id="Lob_EGO_White_Hit">
    <EffectArray value="..."/>   <!-- 伤害，TargetFilters 排除员工 -->
    <EffectArray value="..."/>   <!-- 回 Energy，TargetFilters 只要员工 -->
</CEffectSet>
```

**E.G.O 武器目前一件都没有**，所以这条通道现在没有实物。它会随异想体和 E.G.O 一起长出来——先编一个出来只是在编猜测。测试用 `-sp`。

福利部 lv2 的"白弹（理智恢复）"就是这个东西的第一件成品。

## 只有白伤武器会自动攻击崩溃的员工

这条**只能在数据里做，不能用触发器**——理由你已经知道：脚本下的攻击命令对玩家不生效，玩家的自动攻击是引擎的事。

**武器只按 filter 选目标，没有 validator。**（`CWeapon` 有 `TargetFilters` 和 `AcquireFilters`，没有 `ValidatorArray`——查过了。）所以"这个人崩溃了"必须是一个 **filter 看得见的状态**，而 behavior 只能通过 `Modification` → `StateFlags` 去改这类状态。

能用的那些里，`Passive` 是唯一一个**同时也是真话**的：停止运作的人停止战斗。所以：

```
Lob_Panicked  →  StateFlags Passive
白伤 E.G.O 的第二把武器  →  AcquireFilters 要求 Passive、放行 Ally
其他所有武器             →  什么都不用改
```

最后一行是白捡的：**普通武器本来就不会自动攻击友军**，同盟判定不走 filter 而走引擎的索敌逻辑。所以"其他人不会去打他"不需要写任何东西，需要写的只是"白伤武器会"。

**副作用（有意留下）：** 崩溃的员工自己那把 `GuassRifle` 也会跟着哑火。这正好是基线 §8 的"罢工"，白来的。敌人照旧会打他——敌方武器的 filter 不排除 `Passive`。

> **没验证过的一步：**`AcquireFilters` 放行 `Ally` 之后，自动索敌是不是真的会去打友军。这台机器编译不了地图，所以这一步得等第一把白伤 E.G.O 做出来在游戏里试。机制是齐的（`Passive` 现在已经打上了），不确定的只是引擎肯不肯。

## 休息室不再给崩溃的人回 SP

`Lob_Panicked` 带一条 `StateFlags SuppressEnergyRegen`。

一个 flag 就够，**不用把休息室那个 buff 拆成两个**，而且它只关 Energy：崩溃的员工坐在房间里**伤照样养，脑子不白给**。

于是唯一的出路就是白伤 E.G.O——**在房间里崩溃和在外面崩溃一样，都得有人来管你。**

## 崩溃的样子

### 员工：定在原地

`Lob_Panicked` 的 `Modification`：

| | |
|---|---|
| `AbilClassDisableArray CAbilMove` | 走不了 |
| `StateFlags SuppressEnergyRegen` | 休息室不给回 SP |
| `StateFlags Passive` | 白伤武器认得出他；顺带他自己也不开枪了 |

另外 `11_employee` 在闩上的那一刻补一个 stop——behavior 拦得住新的移动命令，拦不住手上正在执行的那条。

**完整设计是按最高属性分岔**：一个骄傲的人和一个谨慎的人不会以同一种方式散架。那些还没写，所以现在只有一种，取的是"明显是崩溃了、而且好测"这两条。

拒绝派工在 `14_work`：`Work_Refusal` 挡住新工作，`Work_Tick` 丢掉手上那件。缺了前者的话命令会被接受、然后下一 tick 被静默撤销——看起来就是按钮没反应。

### 玩家：失去 E.G.O，慢一点

`Lob_Panicked_Hero`：`CAbilAttack` 关掉（玩家的武器**就是**他的 E.G.O），移速 ×0.85。

**没有 `CAbilMove`。**基线 §8 的"绝不剥夺玩家操作权"在这里原封不动地成立：每一个输入照旧有效，镜头照旧跟随，没有任何硬直。失去的是**打架的能力**，不是**玩的能力**。

冻住一个正握着鼠标的人，和冻住一个 NPC，是两件完全不同的事。

**也没有 `SuppressEnergyRegen`**，所以崩溃的玩家在主休息室里还是能自己回满。这是故意的不对称：员工被定住、有人能去救；玩家谁也救不了——白伤 E.G.O 还不存在，而一个没有任何出路的状态是个陷阱，不是个惩罚。等 E.G.O 落地再回来看这一条。

## 玩家从哪儿掉 SP：没定，而且是故意的

`Lob_Hero_Agent` 有了 Energy，但**没有任何东西会消耗它**。

基线 §8 列的三个来源（黑暗、目睹 NPC 死亡、长时间脱离主休息室）全是 [提案]，而它们要描述的那个游戏——异想体、E.G.O、照明——大部分还不存在。**现在选来源等于替那个游戏做决定。**已经定下来的是"掉光了会怎样"，那部分在上面。

测试用 `-sp me -999`。
