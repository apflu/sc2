## 三件现在就要知道的事

### ~~代码库还是单人的~~ 已修

`c_p0Player` 已经删掉了，全仓库没有任何引用。英雄逐玩家（各自认领、各自复活）、部门逐玩家发（四个上层部门轮着发，满足基线 7.1 的"至少 3 个不同"）、读数把"你的"和"全队的"分开标注。

**新模块一律逐玩家写。**再出现一个 `c_p0Player` 那样的常量就是信号——它长得像配置项，实际上是"只有一个玩家"这个断言，而且会顺着被引用的地方扩散。

### 难度：逐玩家，四档

基线 §2 原本写的是波次"按该玩家自身的发展程度单独缩放"。**这条改掉了**：发展程度不是一个真实的量，得从设备数和升级数里拼一个加权和出来，而且它意味着**你打得越好游戏越难**——那是把跑步机装扮成曲线。

换成 **Casual / Normal / Hard / Brutal**，沿用暴雪战役那套名字，**每名玩家各选各的**。理由不只是"更容易实现"：

- **是选的不是量的**，所以没有人因为玩得好而被惩罚。
- **逐玩家**，所以新人可以在一桌老手里选 Easy 照样学得下去。这和 §4.4 的图鉴准入是同一个形状：难度是每个人实际能承受的东西的函数，而且**不需要当众告诉谁"你是全队被拖慢的原因"**。
- **可以说出口**。"我开的 Hard"是一句话，"我的发展系数是 1.4"不是。

新人开 Casual 也**不会**变成邻居的负担：他那片扇区刷得少，漏出去的自然也少——基线唯一允许的那条负面传导变小了，不是变大。

#### 全局难度 = 全桌的**平均**

个人难度决定个人波。但有两样东西是共享的、因此读不了个人数字：**能源目标**，以及**考验的上限**。

取平均不取最大。基线 §2 已经为全船大潮吵完了这一架——"按全队总量缩放，而非按最强玩家缩放"——理由原封不动搬过来：取最大意味着**一名玩家开 Brutal 就能把全桌拖进午夜考验**，那是一个人的选择伸进了别人的游戏。取平均则每个人只按自己那一份挪动共享数字。

四档难度**一对一**映射四档考验：Casual→黎明，Normal→正午，Hard→黄昏，Brutal→午夜。这不是个待整理的巧合，它就是那个映射。考验本身没做，但**上限做了**——上限是关于难度的事实，不是关于考验的事实。

四舍五入到最近而不是向下取整：三个 Brutal 加一个 Casual 是 2.25，落在 Hard；向下取整会把这桌叫成 Normal 并把考验封在正午，那是一个人的选择替另外三个人做了决定——和取最大是同一个反对意见换个方向。

**能源目标按平均难度缩放**（`Diff_GoalFrom`，Casual 70% / Normal 100% / Hard 125% / Brutal 155%，全是 TUNING）。这正是让个人难度对得起共享目标的那一步：没有它，全桌开 Casual 就是用变弱的对手去打一个没变的目标——那是折扣，不是更小的游戏。有了它，Casual 真的更短、Brutal 真的更长，这才是这个词该有的意思。

正式局里目标只在 init 算一次——难度来自大厅，之后不会动，而 §8.4 那条"大厅在 init 读完、之后不要再依赖它"指向同一个做法。但公式本身放在 `Energy_Retarget()` 里而不是写死在 init 中，因为 `-diff` 会当场改难度：**一个改了设置却让派生值停在旧数上的调试命令，测的是一个正式局里不可能出现的状态。**

通道是**逐玩家的 lobby Game Attribute**（`GameAttributePlayerValue`），也就是 §7.8 给核心抑制挑的同一个通道。属性还没建，读到空串就回落 Normal，所以代码现在就能跑，编辑器里建好之后自动生效、不用改代码。

**考验以后读 `Diff_OrdealCap` 和 `Diff_Of`。**别再长出第二份刻度。

`50_waves.galaxy` 的逐波递增仍然是占位：基线把强度曲线推迟到它要平衡的机制存在之后，而难度是**乘在**那条曲线上的，不是替代它。

## PE-Box 与能源

一次工作产出的箱子**付两次，进两个永不混合的地方**：

- **玩家私有、按异想体分开**的 PE-Box，用来解锁**那一个**异想体的图鉴（观察等级）。不能拿去解锁别的异想体——所以存储就是 `player × abnormality` 的二维格，根本不存在"总数"这个量，也就不存在花错的可能。
- **等额进全局能源池**。攒够（按难度定的）额度后玩家可以**提交**，触发游戏胜利。

能源不违反"不共享钱包"原则：**没有任何东西从里面花出去，也没有任何人的产出速率被别人影响**。它是一块大家一起填的记分板，不是钱包。而且这条设计让"研究异想体"和"赢下这局"变成同一件事，两者不互相抢。

提交是**一个决定**而不是自动结束——够了不代表现在是好时候，可能还有东西在外面跑，或者还有一次工作值得做完。

## 融毁

**点名 → 60 秒内必须有工作"开始" → 否则 Qliphoth 归零，全局能源扣一成。**

四个决定值得记下来，因为它们不是从"融毁"这个词里推出来的：

- **看开始，不看完成。**融毁问的是"派谁去哪一个"，而这个决定在员工迈步的那一刻就已经做完了。看完成的话，第 55 秒派出去的人就是白跑一趟。工作做砸了已经在扣员工 SP，融毁不该再罚一次。
- **归零而不是递减。**融毁是把计数器一次花掉，不是慢慢磨。所以无视一次融毁是一个**决定**，不是一处漏水。计数器归零之后各自做什么仍然没定——那是逐异想体的作者内容，不是规则。
- **被点名时已经有人在里面工作的，倒计时不启动**（`HELD`），一直等到那次工作结束——完成、大门被打掉、员工阵亡或陷入疯狂，四条出口一视同仁。这不是宽容，是同一条规则读仔细了：既然回应方式是"开始一次工作"，而里面的人没法再开始一次，那 60 秒里就有一大段时间**正确操作根本按不出来**。挂起之后，窗口才真的是窗口。
  注意它**不**做的事：在飞的那次工作**不算回应**，因为它开始时还没有任何东西需要回应。它结束之后钟才走，人还是得派。
- **等级全局，点名逐玩家。**共享的是**节拍**不是惩罚。邻居无视自己的融毁，突破的是他自己的异想体，到你这里的是一场架——基线唯一允许的负面传导。你的收入、属性、成功率不因他动一分。
- **能源是唯一的共同代价，而且它合法。**能源是块没人能从里面花钱的记分板，扣它只是把全队推离终点，不改变任何人抵达终点的速率。共享胜利条件允许，共享钱包不允许，这一刀正好切在两者之间。

`Melt_AnsweredBy` / `Melt_MissedBy` 数的是**格子**不是**轮次**。控制部任务 3「妥善处理3轮融毁」读的是轮次，但一个被挂起的格子可以横跨好几轮，"它属于哪一轮"是个有真答案但没有便宜答案的问题。留给第 7 项（任务系统）去定，现在数格子，免得一个凑合的轮次口径被当成正式的。

**归属是空间性的**：先看控制面板的所有者，再退到最近的核心。没有面板也没有核心的收容单元属于 0 号，永远不会被点名——`-melt` 会把它打成 `owner=NOBODY`，因为一个悄悄不被点名的单元和一个坏掉的融毁看起来一模一样。

同轮的附带修正：`Work_Tick_Func` 原来只在**员工死亡**和**异想体出逃**时中断工作。现在**疯狂**和**大门被打掉**也中断了——前者是因为一次糟糕的工作足以把做它的人打崩，而一个已经不运转的人不该还在工作。

## 存档：多人同步是唯一难的部分

bank 是**本地文件**，而 Galaxy 在所有机器上锁步执行。读一个各机器不一致的文件并据此分支，那不是以后会发现的 bug，是**当场 desync**。

引擎的答案是：**已加载的 bank 是被同步的，`BankWait` 就是那道屏障。**这不是推出来的——暴雪自己的战役代码就是这么写的，而且把那个触发器直接命名成了 `ArchivesBankLoadSyncComplete`：

```
BankLoad(name, player)      然后在触发器里：  BankWait(bank)
```

**`BankPreload` 看着像是这里要用的东西，但它不是。**它在 `NativeLib.TriggerLib` 里没有 `<FlagNative/>`，两个参数都带 `<ParamFlagPreload/>`——那是编辑器在编译期收集的声明，不是手写 Galaxy 能调的函数。

`BankWait` 会阻塞，所以它跑在自己的触发器里，用 `TriggerExecute(t, true, false)` 启动（第三个参数是"等它跑完"，关掉）。init 不会卡在几个文件加载后面。

### 两条防止它吃掉别人存档的规则

- **读完之前一个字都不写。**在加载窗口里触发的自动保存会把一张空表盖到真存档上，而丢了四十局图鉴的玩家**没有任何办法知道发生了什么**。`gv_bankLoaded` 门住每一次写。
- **保存由比较驱动，不由调用驱动。**改动观察等级的两个模块（13 买章节、14 加箱子）都排在 bank **之前**，调不进来；而为了修这个把 dirty 标志反向穿过模块顺序，比它要修的问题更糟。所以 bank 自己留一份"上次写下去的快照"，live 表和它对不上就存——行为一样，但没有任何人需要记得去通知谁。

签名开着，但**不拿它当门禁**。§8.2.3：密钥在地图脚本里、扒得出来，而这正是"只存解锁不存数值"最强的论据，不是一个要去打的仗。改一个 flag，你解锁了本来也会解锁的内容；改一个数值会毁掉另外四个人的这局游戏——而这里没有数值可改。

### 以后要压缩：能做，已经验过了

`02_codec.galaxy` 是这件事的**证据**，不是保证：base64 变长整数（每字符 5 位负载 + 1 位续位）加上"多个小字段塞进一个 int"的 `Codec_Put/Get/Drop`。`-codec` 跑往返自检。8 个整数（含 30 位最大值）编码成 20 个字符。

**现在没有任何东西用它，这是故意的。**16_bank 能跑，世界上还不存在任何一个存档文件，而把没测过的代码放进唯一一条能毁掉玩家进度的路径上，换的是没人缺的那点字节。现在值得做的只是**确认这个能力是真的**——因为"以后再压缩"只有在有人验证过之后才算一个计划。

语言侧的结论在 `authoring-contract.md` 的「坑」里：`<<` 和 `|` 确认可用，`>>` `&` `^` `~` 没有证据，所以 codec 用 `/` 和 `%` 代替，一个没见过的运算符都不押。

**真正挡着"全部塞进一个 key"的不是编码，是排序。**现在每个异想体一个 key、key 就是它的类型 id，所以**新加一个异想体不会移动任何已有数据**。压成单串就需要一个**稳定的逐异想体序号**，而这个序号一旦从"文档排序后的下标"来，加一份文档就会把所有人的存档错位。这是个文档侧的决定（跟残余管理难度、"危险"tag 是同一类问题），**不要随手挑一个**。

PE-Box **是存的**，这是明确要求过的："工作获得的 E-Box 会计入存档"。它不属于 §8.1 禁止的那类数字：它买的是知识，永远不进战斗计算，而且**存储里根本没有能让它挪到另一个异想体上的索引**。
